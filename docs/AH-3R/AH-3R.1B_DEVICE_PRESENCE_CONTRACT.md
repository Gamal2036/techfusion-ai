# AH-3R.1B — Device Presence Contract

## Old Inconsistent Behavior

| Problem | Detail |
|---------|--------|
| `Device.lastSeenAt` used `@updatedAt` | Any `prisma.device.update()` (credential rotation, metadata edit, etc.) silently refreshed `lastSeenAt`, making offline devices appear online. |
| Frontend threshold: 120,000 ms (2 min) | Hardcoded `120_000` in 9 locations across 7 files. |
| Backend/reporting threshold: 300,000 ms (5 min) | `reporting.service.ts` used `300000` inline. |
| No shared date utilities | `new Date(...).toLocaleString()` inline everywhere; "Invalid Date" could reach the UI. |
| Metric chart labels | Used raw `new Date(m.recordedAt).toLocaleTimeString()` with no null-safety. |

## Final Presence Definition

A device is **Online** when its `lastSeenAt` timestamp is strictly within the shared threshold from the current time. Otherwise it is **Offline**. Missing, null, or malformed `lastSeenAt` always results in **Offline**.

## Threshold

**`DEVICE_ONLINE_THRESHOLD_MS = 300,000` (5 minutes)**

### Reason

- Agent default telemetry interval: 30 seconds (+0–3 s jitter).
- 5 minutes tolerates up to ~10 missed heartbeats before marking offline.
- Handles transient network issues, brief agent restarts, and scheduled OS sleep/wake.
- Aligns with the reporting service's pre-existing threshold.
- Matches typical IT monitoring conventions.

## lastSeenAt Semantics

**`lastSeenAt` = "The backend successfully received authenticated activity/heartbeat from this device."**

It is explicitly updated **only** during metric ingestion (`ingestMetrics`). It is **not** updated by:
- Credential rotation
- Metadata edits
- Inventory changes
- Admin actions
- Any other unrelated `prisma.device.update()` call

## Metric Timestamp Source

**`recordedAt` is generated by the backend on ingestion.**

- If the agent sends a `timestamp` field, it is validated and stored as `recordedAt`.
- If the agent sends no timestamp, `recordedAt` defaults to `now()`.
- The agent currently always sends `chrono::Utc::now().to_rfc3339()` as the timestamp.
- Frontend receives ISO 8601 strings via the `recordedAt` field.

```json
  "inactive": "boolean",
  "registeredAt": "ISO string",
  "lastSeenAt": "ISO string",
  "agentVersion": "string | null"
}
```

### Latest Device (`GET /devices/:id/latest`)
```json
{
  "device": { /* sanitized device, same as above minus secrets */ },
  "metrics": { "recordedAt": "ISO string", ... },
  "scores": { "calculatedAt": "ISO string", ... }
}
```

- `deviceToken`, `deviceTokenHash`, and `metadata` are stripped by `sanitizeDevice()`.
- Date values serialize as ISO 8601 strings.

|--------|---------|

## Prisma Changes

- Removed `@updatedAt` from `Device.lastSeenAt`.
- Added `@default(now())` to preserve initialization behavior.
- No columns dropped. No data lost. Existing `lastSeenAt` values preserved.

## Migration

**File:** `apps/api-gateway/prisma/migrations/20260725000000_device_lastseenat_explicit/migration.sql`

```sql
ALTER TABLE "Device" ALTER COLUMN "lastSeenAt" SET DEFAULT CURRENT_TIMESTAMP;
```

Safe for existing rows: all Device rows already have a `lastSeenAt` value from the previous `@updatedAt` behavior. The migration only adds a default for future inserts and removes the Prisma auto-update trigger.

## AI Chat Impact

None. AI Chat continues to read live DB metrics via the existing device-context flow. Only the online/offline indicator dot uses the shared `isDeviceOnline` utility.

## WebSocket Scope

WebSocket metric broadcasts were inspected. The `useWebSocket` hook receives real-time metric events and calls `addLiveMetric` which updates the local metrics array. It does not update `lastSeenAt` client-side. The "socket closed before connection established" warning is unrelated to presence and was not modified.

## Manual Validation Steps

1. Start backend, frontend, and agent.
2. Open Device Health list → confirm active device displays **Online**.
3. Open device detail → confirm **Last seen** shows a valid local date/time.
4. Confirm metrics chart x-axis shows valid times (no "Invalid Date").
5. Confirm AI Chat still reads current metrics and shows device context.
6. Stop the agent.
7. Wait 5 minutes (the agreed threshold).
8. Confirm the device changes to **Offline**.
9. Restart the agent.
10. Confirm device returns to **Online** after the next successful metric ingestion (~30s).
11. Perform an unrelated device/admin update (e.g., rename device).
12. Confirm this unrelated update does **not** falsely refresh `lastSeenAt`.
13. Check browser console for date parsing errors.
14. Check backend logs for successful metric ingestion.
